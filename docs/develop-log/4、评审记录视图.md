## 〇、接续开发必读（30 秒速览）

**本阶段做了什么**：把 `Records.vue` 从 P0 占位补全为完整闭环——顶部四维筛选栏（问题 / 模型 / 状态 / 失败标签 + 重置 + 命中数）、`table.tbl.records` 固定列宽 9 列表格、空/无匹配两种 EmptyState、行内「编辑」（复用 P3 `ReviewModal`）/「查看」（进题跳转）。筛选与表格数据由 store 新增的 getter `reviewRows` 统一计算；新增 `focusCaseRound` 支持从记录页跳到该题的对话评审回合。

**最容易踩的坑（本阶段新增）**：
1. **行数据来源是 `askedCases()`，不是全部 reviews**：记录页只展示「在 /chat 真实提问过的问题 × 该题现有回答」（复刻原型 `askedCases`）。所以「只载入演示评审、没提问」时记录页仍是空状态——这是原型行为，勿当 bug。要看到记录必须先提问。
2. **`viewCase` 的跳转要 `flushPromises` 才断言到**：`router.push` 是异步导航，单测里 `trigger('click')` 后必须 `await flushPromises()`，否则读到的还是 `/records`。
3. **列宽对原型有微调**（见 §6.1#1）：为容纳「编辑 / 查看」两个按钮，操作列由 7% 加宽到 12%，相应压缩分维度/失败标签/评语。列顺序仍严格对齐原型。
4. **`chat.focusCaseId` 是交互态、不落盘**：`persistChat()` 未收录它；`ChatReview` 用 `watch(..., { immediate: true })` 消费后立即 `clearFocusCase()`，避免同题二次点击不触发。

**环境与命令**：`npm run dev` / `npm run build` / `npm run test`（当前 **28 用例**：chat-review 8 + review 15 + **records 5**）。

**当前进度**：P0 / P0-B / P1 / P2 / P3 / **P4 已完成**；`src/views/{Leaderboard,Report,LabelDistribution,DataIO}.vue` 仍是占位（属 P5 / P6）。

### 2.2 数据流（UI → store → localStorage）

```
Records.vue
  ├─ 渲染 store.reviewRows（getter）
  │     ├─ store.askedCases ← 各 session.rounds 的 caseId 去重 → cases
  │     └─ 每题 store.answersOf(caseId).map(a => ({c,a,r:getReview(case_id,model_id)}))
  │          → 按 store.filters 四维过滤 → 排序
  ├─ 筛选 v-model 直接改 store.filters.*（响应式，getter 自动重算）
  │     重置 → store.resetFilters()
  ├─ 编辑 → store.openReviewModal(caseId, modelId) → P3 弹窗（草稿态）
  │     保存 → saveReviewModal() → ensureReview + 覆盖 5 维/标签/评语/状态 + persistReviews()（立即）
  └─ 查看 / 题号 → store.focusCaseRound(caseId) + router.push('/chat')
        focusCaseRound：定位含该题的 session → currentId 切过去 → syncSession → expandedRounds=[idx]
                        → chat.focusCaseId = caseId → persistChat()
        ChatReview watch(immediate) → scrollIntoView(#round-idx) → clearFocusCase()
```

### 2.3 筛选实现方式（本阶段提问的重点）

- **唯一收口在 store 的 `reviewRows` getter**，视图层只读 `rows = computed(() => store.reviewRows)`，不重复过滤逻辑，避免视图/榜单两处口径漂移。
- **四个维度逐条 AND**（与原型 `reviewRows` 完全一致）：
  - `caseId !== 'all'` → `x.c.case_id === filters.caseId`
  - `modelId !== 'all'` → `x.a.model_id === filters.modelId`
  - `status !== 'all'` → `x.r.status === filters.status`
  - `label !== 'all'` → `x.r.failures.includes(filters.label)`
- **排序**复刻原型：`case_id` 升序，同题内按 `model_id` 升序（`doubao < qwen < wencai < yuanbao`）。
- **实时联动**由 Vue 响应式天然保证：`filters` 是 store 的响应式对象，`v-model` 改动即触发 getter 重算与重渲染，无需手动 `renderRecords()`。
- 顶部「命中 N 条」= `rows.length`；「重置筛选」= `resetFilters()` 把 `filters` 换回全 `all` 的新对象。

### 2.4 跨视图联动与持久化

- **保存路径**：`saveReviewModal()` 写回 `reviews[key]` 后**立即** `persistReviews()`（不走 P3 的 260ms 防抖），因此表格即时更新且刷新不丢。
- **共用同一份 `store.reviews`**：记录页、对话评审卡、排行榜/报告的 `aggregate()` 都读它，所以「改一处、处处变」；单测用 `aggregate('FQ-001', …)` 证明改分后题均分与标签计数同步变化（无引用 bug）。
- **进题查看复用了 P2 的会话/回合渲染**：不新建「单题四模型」页面，直接把用户带回 /chat 的对应回合（展开并滚动），符合「至少一种进题查看方式」。

## 三、关键技术选型与架构决策

1. **`reviewRows` 放 getter 而非视图 computed**：筛选口径要被测试与其他视图复用，放 store 可单测、可复用；视图只做展示。getter 内用 `this.askedCases` / `this.answersOf` / `this.getReview`（Pinia options getter 的 `this` 即 store 实例）。
2. **`askedCases` / `reviewRows` 与原型逐行对齐**：包括「只统计真实提问过的问题」「空白回答也成行（状态未评审）」这两条易被忽略的行为。
3. **模型下拉用 `store.allModels()`（内置 4 + 自定义）**：原型下拉只列 4 个内置模型，但用户 P4 明确要「4 内置 / 自定义」，故用 `allModels()`（无自定义时与原型等价）。见 §6.1#2。
4. **进题查看用「store 交互态 + 路由 + watch」而非 hash / query**：`chat.focusCaseId` 作一次性信号，`ChatReview` 挂载时 `immediate` 消费并滚动，用后即清；不复用 URL，避免刷新后重复滚动。
5. **空状态分两种**（复刻原型）：未提问 → 整页空状态（不显示筛选）；已提问但筛选无命中 → 保留筛选栏 + 「没有符合条件的评审记录」。两者都提供回到「对话评审」/重置的出口。
6. **题号做成 `<button class="qnum">`**：原型是 `<span class="qnum">`，本阶段加可点能力（用户明确要「点题号进题查看」），样式沿用 `.qnum`，仅补 `border:0` 与 hover 底色。

## 六、交互路径说明（交付说明）

1. 进 `/records`：若还没提问过 → 空状态「还没有提问。…」+「去对话评审」按钮；若有提问 → 顶部筛选栏 + 记录表。
2. 筛选栏 4 个下拉实时联动，右侧「命中 N 条」随之变化；「重置筛选」恢复全量。
3. 表格列（原序列）：问题（蓝色题号，可点）/ 模型（色点 + 名）/ 状态（已完成·绿 / 评审中·橙 / 未评审·灰）/ 总分 / 分维度（`数 / 引 / 时 / 安 / 质`，低分红色）/ 失败标签（单行截断）/ 评语（两行截断）/ 评审时间 / 操作（编辑·查看）。
4. 点「编辑」→ 打开 P3「编辑评审」弹窗，改分 / 标签 / 评语 / 状态 → 保存 → 表格即时更新 + toast。
5. 点题号或「查看」→ 跳到 `/chat` 并展开、滚动到该题的对话评审回合（该题的模型卡）。
6. 刷新页面：编辑后的分数 / 标签 / 评语仍在（`faeval.v1.reviews` 已落盘）。

- ⚠️ **`chat.focusCaseId` 不要写进 `persistChat()`**：它是交互态，落盘会导致刷新后重复滚动。
