## 〇、接续开发必读（30 秒速览）

**本阶段做了什么**：把 `DataIO.vue` 从占位补全为完整的「数据导入导出」页；在 `lib/export.js` 新增 **`buildExport(scope)`**（全量 / 仅评审 / 仅回答）与 **`buildReportData()`**（报告数据装配纯函数），并扩展 `reportMarkdown()`；store 新增导出 / 导入 / 演示数据管理 / 报告 action；新增 Node 脚本 `scripts/report.mjs`（`npm run report`）保证报告「程序生成」可复现。

**最容易踩的坑（本阶段新增）**：
1. **导出 / 导入的合并口径必须复刻原型 `importData`**：`cases` 按 `case_id` 合并；`answers` 一律标记 `custom:true` 并按 `id` 去重覆盖；`reviews` 按 `(case_id,model_id)` 覆盖；分数线 **clamp 0–5**；非法 `status` 回落 `none`。导入后 `review.demo` 一律置 `false`。
2. **`replace`（替换内置题目与回答）语义**：开启时 `answersStore.custom` 被整体替换且 `deleted` 清空——即「导出里没有的内置回答」无法保留「被删除」状态（导出只含 `answersOf` 可见回答，原型如此）。
3. **导出 JSON 的 `models` 固定为内置 `MODELS`（4 个）**，不是 `allModels()`（原型 `buildExport` 即如此）。因此「四模型对比报告」口径成立；自定义模型不入导出。
4. **报告 Markdown 的表格分隔行必须与表头列数一致**：用数组 `cols.map(()=>'---')` 生成，勿用字符串拼接（曾出现 `---|------` 这类合并 dash，渲染无碍但观感差）。
5. **报告 / 页面共用 `buildReportData`**：`Report.vue` 不再自行算 `totalAns/status/agg/matrix`，改由该纯函数取数，保证「导出的 .md」与页面数值一致。
6. **Node 直接加载 `lib`**：`scoring.js` / `export.js` 的内部 import 已改 **相对路径（带 `.js`）**，否则 `scripts/report.mjs` 无法解析 `@/` 别名。

**环境与命令**：`npm run dev` / `npm run build` / `npm run test`（当前 **51 用例**：chat-review 8 + review 15 + records 5 + analysis 10 + **dataio 13**）/ **`npm run report`**（生成 `report.md`）。

**当前进度**：P0–P6 **全部完成**；仅「回合级操作 / 浏览器像素级视觉核对」等遗留见 §7。

### 1.1 目标（用户 P6 原文要点）

1. **导出（复刻 `buildExport`）**：导出全部 / 仅评审记录 / 仅回答；复制 JSON 到剪贴板；文件名形如 `竞技场-全量-YYYYMMDD.json`；中文 UTF-8 不乱码（`TextEncoder→base64` data URL，失败回退 blob）。

### 2.2 数据流


## 三、关键技术选型与架构决策

1. **`buildExport` 与 `buildReportData` 均为 `lib/export.js` 内的纯函数**：导出与报告不依赖 store，浏览器与 Node 共用；`Report.vue` 也借此与 `reportMarkdown` 同口径。
2. **导入逻辑放 store action（`importData`）**：需要写 `cases/answersStore/reviews` 并落盘，天然属于 store；返回成功项数组供 UI 判断。
3. **`lib` 内部改相对 import + `.js` 后缀**：让纯逻辑层可被 Node 直接 import，无需引入 `vite-node` 等依赖，也不改动全局别名（视图/测试仍用 `@/`）。
4. **报告脚本默认回退内置演示数据**：`npm run report` 开箱即可复现「四模型对比报告」；同时接受 `report-input.json` 或命令行路径读取真实导出 JSON。
5. **`details.ref` 折叠快照**：复刻原型，默认 `open`；等宽小字号只读文本域。
