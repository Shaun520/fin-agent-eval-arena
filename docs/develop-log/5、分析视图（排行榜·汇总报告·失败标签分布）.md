## 〇、接续开发必读（30 秒速览）

**本阶段做了什么**：把 `Leaderboard.vue` / `Report.vue` / `LabelDistribution.vue` 三个 P0 占位补全为完整分析视图，并新增两个原生 SVG 图表组件（`DimGroupedChart.vue` / `LabelBars.vue`）。聚合口径全部复用 `src/lib/scoring.js` 既有纯函数（`aggregate` / `reviewTotal` / `countLabels` / `isSolved`），视图内只做「取数 → 渲染」，未改动 store。

**最容易踩的坑（本阶段新增）**：
1. **分析视图与记录页口径不同**：记录页（P4）只围绕 `askedCases`（真实提问过的问题）；而**排行榜 / 汇总报告的聚合用「全部 reviews」**（复刻原型 `solvedReviews()` / `allReviews()`），只在「是否进入页面」上由 `askedCases().length` 把关。即：**载入演示评审后，只要提问过任意一题，排行榜就会把 5 道题的演示记录全部统计进来**。这不是 bug，勿改。
2. **`askedCases().length === 0` 时排行榜/报告走引导空态**（`askedEmptyState`），此时**连范围选择卡都不渲染**；而已提问但无 `solved` 记录时，**保留范围卡 + 空提示**。两种空态不一样。
3. **统计卡「已完成评审 / 完成率」按 `askedCases × answersOf` 口径**（复刻原型 `countStatus()`），与「标签分布页的 reviewed 条数（全部 reviews）」口径不同；日志已标注，勿统一。
4. **报告矩阵每格的「均分」只累加 `status==='done' && reviewTotal!==null`，但「Top3 失败标签」统计该题全部回答的 failures**（含评审中），与原型一致。
5. **分维度柱状图固定用内置 4 模型（`MODELS`）**：用户验收明确「每组 4 根柱」；排行榜/汇总表用 `allModels()`（含自定义）。二者口径差异是有意为之。
6. **单测里连续两个 store 要 `localStorage.clear()`**：`loadDemoReviews()` 会落盘，若不清理，后建的 store 会从 localStorage 恢复出演示评审（本阶段踩过，见 §4#1）。

**环境与命令**：`npm run dev` / `npm run build` / `npm run test`（当前 **38 用例**：chat-review 8 + review 15 + records 5 + **analysis 10**）。

**当前进度**：P0 / P0-B / P1 / P2 / P3 / P4 / **P5 已完成**；`src/views/DataIO.vue` 仍是占位（属 P6）。

## 一、本阶段的目标与需求背景

### 1.1 目标（用户 P5 原文要点）

1. **模型排行榜**：顶部统计范围选择（全部问题 / 单题）+ 样本说明 + 「复制排行榜(Markdown)」；排行榜（名次 / 模型色点+名+基准 chip / 横向进度条 / 总分 / 覆盖题数）；分维度分组柱状图（原生 SVG）；分维度明细表（排名|模型|题均总分|各维均分(权重%)|覆盖题数）；仅纳入「已完成且五维齐全」；无数据引导空态。
2. **汇总报告**：4 个 StatCard（问题数 / 回答数 / 已完成评审 / 完成率）；`status=done` 但维度缺失的排除 banner + 「去处理」跳转；各模型汇总表；失败标签总体分布条形图；问题×模型对比矩阵（总分色阶 ≥85 绿 / ≥70 橙 / 其余红 + 状态 chip + 行尾均分与 Top3 标签）；「导出汇总报告(Markdown)」。
3. **失败标签分布**：全部模型标签条形图 + 标签×模型命中矩阵（数值用模型色）+ 标签含义与判定建议表。
4. 图表组件化 SVG，props 传聚合结果，宽度 100% 响应式。

### 2.2 数据流

```
Leaderboard.vue
  ├─ agg = aggregate(store.leaderboardCase, { reviews: store.allReviews, models: store.allModels() })
  │     └─ store.leaderboardCase: 'all' | caseId（v-model 直接改 store 态，无需持久化）
  ├─ ranked = allModels().map(m => ({ m, s: agg.byModel[m.id] })).sort(avg 降序, null 垫底)
  ├─ DimGroupedChart :by-model="agg.byModel"（内部固定 MODELS 4 色）
  └─ 复制 → leaderboardMarkdown({scopeLabel, sampleN: agg.n, agg, models}) → copyText → toast

Report.vue
  ├─ totalAns  = Σ askedCases.answersOf().length
  ├─ status    = Σ getReview(askedCases × answersOf).status（复刻 countStatus）
  ├─ agg       = aggregate('all', …)
  ├─ allLabels = countLabels(allReviews.filter(hasAnyReviewContent))
  ├─ unfinished= allReviews.filter(r => r.status==='done' && reviewTotal(r)===null)
  ├─ matrix    = askedCases.map(题 => { cells(逐模型 t/status), avg, topLabels })
  └─ 导出 → reportMarkdown(...) → downloadFile(..., '.md', 'text/markdown')

LabelDistribution.vue
  ├─ reviewed = allReviews.filter(hasAnyReviewContent)
  ├─ allLabels = countLabels(reviewed)
  ├─ perModel  = MODELS.map(m => countLabels(reviewed.filter(model_id===m.id)))
  └─ 判定说明表直接遍历 FAILURE_LABELS
```

### 2.3 与原型渲染的逐条对齐（易被忽略）

- 排行榜行栅格 `26px 130px 1fr 62px 150px`、进度条 `v/100*100%`、基准 chip 仅在 `m.baseline`。
- 柱状图几何：`gw=(W-padL-padR)/5`、柱组起点 `padL+gw*i+14`、柱宽 `bw-4`、`bw=(gw-28)/4`、某模型某维为 `null` 则该柱不渲染。
- 标签条形图：`Math.max(1, …)` 兜底除零；色 `sev==='high'?'var(--danger)':'var(--warn)'`。
- 矩阵总分色阶与 `statusChip` 文案（已完成绿 / 评审中橙 / 未评审灰）；Top3 标签 `chip(...,'danger')` 带 `×N`。

## 三、关键技术选型与架构决策

1. **聚合口径全部下沉到 `lib/scoring.js` 纯函数**：视图不重复实现加权/筛选逻辑，避免四处口径漂移；本轮零改动 store，回归风险最小。
2. **图表组件用「聚合结果」props 而非自己取 store**：`DimGroupedChart` / `LabelBars` 是纯展示组件，便于复用与单测（可直接断言 `props('counts')`）。
3. **报告文本走纯函数 + 调用方传数**：`leaderboardMarkdown` / `reportMarkdown` 不依赖 store，既能被视图调用，也能被测试直接断言，且 URL/下载/剪贴板互不耦合。
4. **`copyText` 放 `lib/export.js`**：与 `downloadFile` 同属「产出层」，`navigator.clipboard` 失败回落 `execCommand`，失败返回布尔供视图决定 toast 文案。
5. **空态分三档**：未提问（引导去对话评审）/ 已提问无 solved（保留范围卡 + 提示）/ 无评审内容（标签页），逐条复刻原型。
