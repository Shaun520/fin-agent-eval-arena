### 1.4 统一命名口径（导出 / 导入 / 存储都依赖，不可改）

- **5 个评分维度**：`accuracy` 数字正确性 0.30 / `citation` 引用与证据 0.15 / `timeliness` 数据时效性 0.15 / `safety` 安全合规 0.25 / `quality` 回答质量 0.15；单维 0–5 分（整数）。
- **总分公式**：`total = Σ(score / 5 × weight) × 100`，保留 1 位小数。
- **8 个失败标签**：`num_error` 数字错误(高危) / `unit_error` 单位错误(高危) / `invalid_citation` 引用无效(一般) / `future_data` 使用未来数据(高危) / `stale_data` 数据过时(一般) / `risk_missed` 风险漏报(高危) / `unfounded_advice` 无依据买卖建议(高危) / `causal_misstate` 因果关系表述不当(一般)。标签只作归因，**不自动扣分**。
- **评审状态**：`none` 未评审 / `doing` 评审中 / `done` 已完成。
- **4 个内置模型**：`wencai` 同花顺问财(#d92b2b, 基准) / `doubao` 豆包(#2b6ef6) / `qwen` 千问(#7b5cf0) / `yuanbao` 腾讯元宝(#0e9f6e)。
- **导出 schema 标识**：`fin-agent-eval/v1`；**localStorage key 前缀**：`faeval.v1.`。
- **实体字段**：
  - `case{case_id, title, question, reference_answer, reference_values[{name,value,unit}], allowed_evidence[{title,org,published_at}], cutoff_at, risk_labels[], focus}`（另有内部字段 `free: true` 表示自由提问）
  - `answer{id, case_id, model_id, answer, citations[{title,org,published_at}], generated_at, latency_ms?, cost_cny?}`（本地录入另有 `custom: true`）
  - `review{case_id, model_id, scores{5 维}, failures[], comment, status, reviewed_at, updated_at}`（运行时另有 `demo: true` 标记演示记录）

## 三、关键技术选型、实现思路与架构决策

1. **Tailwind 选 v3.4 而非 v4**：需求明确要求「用 `tailwind.config` 的 `theme.extend` 承载 `:root` 设计令牌」，v3 的 JS 配置形态与此吻合（v4 为 CSS-first，需 `@config` 变通）。
2. **设计令牌双处同源**：`tailwind.config.js` 的 `theme.extend`（`colors.bg/sidebar/border/content/muted/brand/ok/warn/danger/risk`、`borderRadius.lg/md/sm`、`fontSize.11–22`、`boxShadow.card`、`fontFamily.sans/mono`）+ `main.css` 的 `:root` CSS 变量。理由：Tailwind 类用于新写的模板，`var(--x)` 用于必须与原型逐字对齐的样式（含原型内联样式里引用的变量）。
3. **基础类放 `@layer components` 而非全用工具类**：原型的 `.btn / .card / .chip / .tbl / .ctl` 有大量伪类、`[disabled]`、`@media` 分支，用工具类逐个改写在视觉上会漂移。故把原型 CSS **逐条**搬进 `@layer components`（`utilities` 层在后，仍可被工具类覆盖）。
4. **路由懒加载 + `meta` 承载顶栏文案**：6 个视图用 `() => import()`；`VIEW_META` / `NAV_SEGMENTS` / `SEG_LABEL` 统一放在 `src/router/index.js`，避免多文件维护导航文案（对应原型的 `VIEW_META` / `NAV_SEGMENTS`）。
5. **`answersStore` 三层结构（P0-A 原型没有，P1 明确要求）**：`builtin`（内置只读，始终来自 `answers.json`，**不落盘**）/ `custom`（本地录入与导入，同 `id` 覆盖内置）/ `deleted`（被删内置回答的 `id` 列表）。`answersOf(caseId)` 的合并顺序必须保持：先剔除 `deleted`，再用 `custom` 覆盖同 `id` 的 `builtin`，最后 `base.concat(custom)`（**custom 在后**，保证顺序稳定）。
6. **localStorage 键与原型的存储兼容**：`faeval.v1.reviews` 存 `reviews` 映射本身；`faeval.v1.answers` **只写 `{custom, deleted}`**（原型如此，不能把 `builtin` 写进去）；`faeval.v1.chat` 只写持久字段（`sessions / currentId / active / customModels / reviewMode / selected / animated`），编辑态与弹层态不落盘。
7. **`getReview` 只读、`ensureReview` 才写入**：渲染路径一律用 `getReview`（返回 `blankReview` 副本，不污染 `state.reviews`），只有用户产生变更时才 `ensureReview` 建记录；配合 `pruneEmpty` 在变更后清掉「无内容且 status=none 且非 demo」的空记录。
8. **评分纯函数化**：`aggregate` 设计为 `aggregate(scope, { reviews, models })`，自身完成「`status=done` 且五维齐全」的过滤，不读全局、可直接单测；`weightedTotal` 对未打分维度 **跳过**（与按 0 计数值等价，但语义更明确）；`reviewTotal` 在五维未齐时返回 `null`。
9. **`scoreClass(v)` 判定顺序**：`null → 'low'`；`<= 3 → 'low'`（红）；`<= 3.5 → 'mid'`（橙）；否则 `''`。**顺序不能颠倒**（先判 `<=3`）。
10. **流式输出引擎抽到 `lib/stream.js`**：`streamText(full, { speed, delay, onUpdate, onDone })` 用定频 `setInterval`（`STREAM_TICK_MS = 24`）+ delta-time 累加字符，不依赖 `requestAnimationFrame`——原型注释明确指出这是为了在无头浏览器 / 后台标签页 / 低帧率下不卡住。`off` 模式（`Infinity`）直接整段输出。
11. **Toast 状态收进 store**：P0 时 `Toast.vue` 自持 `ref`，P1 改为渲染 `store.toasts` 并由 `store.toast(msg, isErr)` 入队，保证全局单一份队列（原型的实现是模块级 DOM 操作，此处是等价的 Vue 化）。
12. **`loadState()` 在 `mount()` 之前调用**：这样 Pinia devtools 里看到的初始 state 就是已恢复的，而不是「先空再灌」。首次运行会种入 `cases.json` 并写 `faeval.v1.seeded` 标记，避免重复灌入；**`reviews` 保持为空**（原型明确规定：内置参考问题一律从未评审开始，不预置演示评分）。
