**最容易踩的坑（本阶段新增）**：
1. **弹窗组件必须自守 `reviewModal === null`**：`saveReviewModal()` / `closeReviewModal()` 会把 `store.reviewModal` 置 `null`，但组件卸载前还可能被调度一次重渲染；模板里直接读 `m.drafts` 会抛 `Cannot read properties of null`。已在 `ReviewModal.vue` 用 `<template v-if="m">` 包住全部主体内容。App.vue 的 `v-if` 不能替代这个守卫。
2. **接口 ≠ 原型全部行为**：本阶段有多处偏离原型的「用户口径」改动，见 §6.1，务必知悉，勿按原型「顺手改回去」；反之，§1.4 的三处「按原型回退」也不要再改回来。
3. **`setScore` 是 toggle**：对同一分值再点一次会把该维度清空（原型如此）。浏览器冒烟测试里「点已满分的 5」表现为取消，属预期。
4. **测试里用假定时器要限制范围**：`vi.useFakeTimers({ toFake: ['setTimeout','clearTimeout'] })`，不要默认全量假造（会波及其它全局对象）。

**环境与命令**：`npm run dev` / `npm run build` / `npm run test`（当前 **23 用例**：chat-review 8 + review 15）。

**当前进度**：P0 / P0-B / P1 / P2 / **P3 已完成**；`src/views/{Records,Leaderboard,Report,LabelDistribution,DataIO}.vue` 仍是占位。

## 一、本阶段的目标与需求背景

### 1.1 目标（用户 P3 原文要点）

1. **答案卡片内联评审区（复刻 `.rv`）**：5 行维度打分（维度名 + 权重小字 / 0–5 分按钮组 `.scale`，选中态低分红·中档橙·达标蓝 / 行末维度分值）+ 行末加权总分 `.total-mini`；8 个可多选 `.tag`；评语 textarea + 自动保存提示 `.draft-note`；保存 / 提交 / 重新提交；卡头 ✎ 可解锁重新编辑。（原稿还要求「状态三态 `.status-seg`」，**已在 §1.4 按原型回退移除**；评审状态仍可在弹窗内改。）
2. **校验**：提交时若存在维度未打分 → toast 提示缺失维度名，**不允许置为 done**。
3. **单卡片增量刷新**：打分 / 切标签 / 改状态只更新该卡片局部 DOM（复刻 `refreshCard`），不整页重渲染，避免打断流式动画。
4. **评审编辑弹窗（复刻 `.modal`）**：`openReviewModal(caseId, modelId)` 打开、遮罩点击关闭；题目摘要 2 行截断 + 5 维 + 标签 + 评语（自动增高、超出滚动）+ 状态 + 底部取消/保存；`saveReviewModal` 写回并落盘。
5. **自动保存**：评分变更去抖 260ms 后 `persistReviews`；点提交立即持久化。
6. **持久化与恢复**：全部 review 存 localStorage，刷新后分数 / 标签 / 评语 / 状态 / 锁定态完整恢复；已 done 默认锁定，需点 ✎ 才能改。
7. **演示数据**：一键载入 20 条演示评审，也可一键清空；不影响用户自建记录。

### 2.2 评分数据流（UI → store → localStorage）

```
用户点 .scale 按钮（ReviewPanel）
   → store.setScore(caseId, modelId, dim, v)
        ├─ isLocked? 已提交且未编辑 → toast 拦截并 return
        ├─ ensureReview() 建/取记录；r.scores[dim] = (原值===v ? null : v)   ← toggle
        ├─ 状态 none 且有内容 → doing
        └─ touchReview(immediate=false) → updated_at/demo=false → pruneEmpty()
                                        → schedulePersistReviews()（260ms 防抖）

标签 .tag  → toggleTag()  → 同上（防抖落盘）
评语 textarea → setComment() → 同上（防抖落盘）+ 面板本地「输入中…自动保存」→「已自动保存 HH:MM」（.saved 变绿）
状态（仅弹窗内改）→ setStatus(s)
        ├─ s==='done' 且缺维度 → toast 拦截，不置 done
        └─ 否则写入；touchReview(immediate=true)  ← 状态变更立即落盘
提交按钮 → submitReview()：
        ├─ missingDims().length → toast「还有未打分的维度，无法提交：…」并 return false
        └─ 否则 done + reviewed_at/updated_at + 清空 chat.editing + persistReviews()（立即）
保存评审 → saveReview()：锁定则 return；否则 status none→doing + 立即落盘 + toast
清空评分 → resetReview()：锁定则拦截；否则 delete reviews[key] + 立即落盘
导出本轮 → exportRound(caseId)：buildCaseExport(...内存中的最新 reviews...) → downloadJSON(...) → toast
        （读内存态，因此不依赖 260ms 防抖是否已落盘）

store.persistReviews() → lsSet('faeval.v1.reviews', state.reviews)
```

### 2.3 持久化与恢复路径

```
刷新 → src/main.js: useArenaStore(pinia).loadState()
   → const saved = lsGet('faeval.v1.reviews', null)
   → this.reviews = (saved && typeof saved === 'object') ? saved : {}
   → 各组件用 store.getReview(caseId, modelId) 读取
      （只读，不写入；无记录时返回 blankReview 副本）
   → ReviewPanel 渲染 scores / failures / comment / status；AnswerCard 渲染头部总分与状态胶囊
   → 锁定态由 isLocked = (status==='done' && !isEditingCard) 推导；
      chat.editing 是「交互态」，persistChat() 不落盘 → 刷新后自动回到锁定
```

`faeval.v1.reviews` 始终存整个 `reviews` 映射本身（键 `caseId||modelId`），与原型一致；demo 记录仅多一个运行时字段 `demo: true`，`clearDemoReviews()` 只删它。

### 2.4 单卡片增量刷新（未做整页重渲染）

Vue 响应式天然满足「局部更新」：`.scale/.tag/textarea` 的事件只改 `store.reviews[key]` 的响应式字段，只有 `ReviewPanel`、`AnswerCard` 头部、`ChatRound` 的进度/收起态 `mini-score` 依赖它。`AnswerCard` 的流式状态是**本地 ref**（`shown/streaming/citeShown`）且 `onMounted` 只跑一次、`:key="a.id"` 稳定，因此重渲染不会重播动画。本阶段未引入任何 `renderView()` 式全量重绘。

## 三、关键技术选型与架构决策

1. **`ScoreDim.vue` 抽成共享子组件**：原型 `.dim` 行在卡片与弹窗里结构逐字相同（弹窗只是 `.scale button` 尺寸不同，靠 `.modal-body .scale button` 覆盖）。两处若各写一遍 5 行模板会明显重复，抽一个「单维行」是合理粒度，不算过度抽象。
2. **弹窗状态放 store（`reviewModal`）而不是组件内**：原型 `state.modal` 是全局草稿；P4「评审记录」页的编辑按钮也要调 `openReviewModal`。放 store 才能被任意页面复用，且 `App.vue` 全局挂载即可。草稿**不落盘**（交互态）。
3. **防抖落盘的收口**：`touchReview(caseId, modelId, immediate)` 是唯一收尾入口。评分/标签/评语走 `schedulePersistReviews()`（260ms，模块级单例 timer）；状态切换与提交/保存走 `immediate=true`。这样既满足「评分变更去抖」，又保证「点提交立即持久化」，不会因为防抖丢状态迁移。
4. **「缺维度不允许 done」做在 store 层**：`submitReview` 与 `setStatus('done')` 共用 `missingDims()` 拦截。UI 只负责禁用/提示，规则单点可测（原型「已标记完成但提示缺失」的宽松口径改为硬拦截，属用户明确要求）。
5. **锁定判定 `isLocked` 收敛到 store**：原先 `setScore/toggleTag` 各自内联 `status==='done' && !isEditingCard(...)`，现统一为 `isLocked()`，`resetReview`/`saveReview` 也复用，避免多处漂移。
6. **弹窗复用 `common/Modal.vue`**：它已有遮罩点击关闭（`@click.self`）+ ESC + head/body/foot 插槽，正好对应 `.modal-mask/.modal/.modal-head/.modal-body/.modal-foot`，无需新写弹层。
7. **演示数据保护**：`loadDemoReviews()` 遇到「已存在且非 demo」的记录会跳过，避免覆盖用户真实评审；`clearDemoReviews()` 只删 `demo===true`。两者都写/清 `faeval.v1.seeded`。

> ⚠️ **§1.4 三处修订后的浏览器复测被中断，未出结论**：这三处（移除问题卡片、移除卡片内三态状态、新增导出本轮）目前只有「单测 + 构建」证据，尚无浏览器人工确认。复核要点：轮次里不再有问题卡片；「收起」右侧有「导出本轮」且点击后弹 toast「已导出「{主题}」（含评审）」并下载 `fin-agent-eval-case{N}-{时间戳}.json`；模型卡内不再有「评审状态」段（卡头胶囊仍在）。

### 5.3 未能覆盖的项

- 像素级视觉核对（`.dim` 网格 118px、`.scale` 24px/22px、圆角与阴影）仍依赖人工；自动化只验证了行为与关键数值。
- 弹窗（`ReviewModal`）的**真实 UI 入口**本阶段不存在（按决策由 P4 接入），其正确性由组件单测覆盖，未在浏览器里人工点开过。
- 「导出本轮」的**文件落盘结果**未在浏览器里核对（单测只断言载荷结构与 toast 文案）。

## 六、交互路径说明（交付说明）

1. 进 `/chat` 空状态 →「演示数据」行可「载入演示评审记录（20 条）」或「清空演示记录（n）」。
2. 提问后，轮次结构为：用户气泡 + meta（N 个模型作答 · 时间 · 本轮进度 x/y · 收起 · **导出本轮**）→ 答案网格（不再有问题卡片）。
3. 答案卡正文下方即为评审区：5 行维度、加权总分、失败标签、评语、操作行（**不含**评审状态三态）。
4. 未提交的记录可直接打分/勾标签/写评语；**提交**后卡头显示「已完成」并锁定全部评分控件。
5. 锁定后点卡头 **✎**：出现蓝色「评分编辑中」角标、控件解锁；改完点 **重新提交** 即写回并再次锁定。
6. 提交时若五维未打满 → 右下角 toast 报出缺失维度名，状态不变。
7. 评语输入时 `.draft-note` 显示「输入中…自动保存」，260ms 后变为绿色的「已自动保存 HH:MM」。
8. 点「导出本轮」→ 下载 `fin-agent-eval-case{N}-{时间戳}.json`（该题题目 + 回答 + 该题评审 + 配置/模型元数据），并 toast「已导出「{主题}」（含评审）」。
9. 刷新页面：分数 / 标签 / 评语 / 状态全部恢复，且已提交记录回到锁定态（`chat.editing` 不落盘）。

### 6.1 与原型的有意差异（**需知悉，勿当作 bug 改回**）

| # | 差异 | 说明 |
|---|---|---|
| 1 | **提交时缺维度 → 硬拦截** | 原型 `submit-review` / `setStatus('done')` 是「置 done + toast 提醒缺维度」；改为不允许置 done（用户验收要求） |
| 2 | **锁定态下 保存/清空 也禁用** | 原型操作行按钮恒可用（`rv-actions` 未加 `rv-ghost`，实际一直显示）。本阶段在 `done && !editing` 时把三个按钮一并禁用，符合「锁定控件」 |
| 3 | **加权总分行未评完显示「未评完」（灰）** | 需求文字写「—」，原型写「未评完」；按原型实现 |
| 4 | **演示数据入口在对话评审空状态** | 原型在「数据导入导出」页；本阶段按用户决策前移，P6 再补数据页 |
| 5 | **`loadDemoReviews` 不覆盖自建记录** | 原型会无条件覆盖同键；本阶段跳过「已存在且非 demo」的键。故如果用户在演示覆盖的 20 个 (题,模型) 上已有真实评分，实际载入数会少于 20，toast 会显示真实条数 |
| 6 | **评分变更 260ms 防抖落盘** | 原型 `setScore/toggleTag` 是立即落盘、只有评语防抖；按用户 P3 要求统一为防抖，提交类动作仍立即落盘 |
| 7 | **弹窗无 in-app 入口** | 按决策由 P4「评审记录」的编辑按钮接入 |
| 8 | **导出只实现了单轮（case）范围** | 原型 `buildExport` 另有 `all/reviews/answers` 三种范围与「复制 JSON」，属数据导入导出阶段（P6）；本阶段只落 `buildCaseExport` |
