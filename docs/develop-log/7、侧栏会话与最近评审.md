**最容易踩的坑（本阶段新增）**：
1. **会话标题口径**（`sessionTitle`）：显式 `title` 且非「新会话」→ 用它；否则取首轮内容（`kind==='chat'` 取 `text`，否则 `caseById(caseId).question || .title`），统一截 **14 字**；无轮次 → 「新会话」。
2. **`deleteSession` 用 `window.confirm`**，文案必须逐字复刻原型（含 `\n`），删除仅移除对话记录、**不动 `reviews`**；删空自动补一个新会话；删当前则切到 `sessions[0]`。
3. **`recentRounds` 只统计当前会话**（`state.chat.rounds`）中 `kind !== 'chat'` 的轮次，并带 `rounds` 下标（供展开定位）；题目已被删除的轮次跳过（复刻原型 `caseById` 为空即跳过）。
4. **展开/收起复用已有 `toggleRound / isRoundExpanded`**，不新增机制；点「最近评审」= 切换展开态 + `scrollIntoView`（与原型 `expand-round` 一致，**不额外跳转路由**）。
5. **Pinia 响应式数组引用比较**：`chat.rounds` 是 reactive 代理，与原始 `s.rounds` 不是同一引用；单测里要比较引用必须两边都经 reactive 路径取（如 `store.chat.sessions[0].rounds`），否则 `toBe` 会失败。
6. **有意的偏离**：原型 `recent` 块在非评审分组下仍会渲染「最近评审 / 还没有评审」（其代码如此，但同处注释写「只在评审分组下展示」）。本实现按注释意图与已确认方案，**两块都仅在 `seg==='review'` 渲染**。

## 一、本阶段的目标与需求背景

### 1.1 目标（用户 P7 原文要点）

1. **会话列表**：侧栏展示当前全部会话（标题 + 轮次数），支持 **新建 / 切换 / 删除**。
2. **最近评审**：只列当前会话的评审轮（日常对话不入），显示题面（截 14 字）与该题 `done/total`，点击展开并滚动定位。
3. 两块**仅在「评审」分组**下展示；切换会话后「最近评审」随之切换。
4. 会话与当前会话经 `localStorage` 持久化，刷新可恢复（沿用既有 `persistChat / loadState`）。

### 2.2 数据流

```
AppSidebar.vue（seg === 'review'）
  ├─ 会话块  store.chat.sessions  →  sessionTitle(s) / s.rounds.length
  │     ＋ 新建 → store.createSession()   （unshift + 切当前 + 落盘 + toast）
  │     点会话项 → store.switchSession(id)（改 currentId + syncSession + 落盘）
  │     点 ✕     → store.deleteSession(id)（confirm → 过滤 → 补位 → 落盘 + toast）
  └─ 最近评审块  store.recentRounds（当前会话 kind!=='chat' 且题目存在）
```

### 2.3 新增 action 行为对照（复刻原型）

| action | 行为 |
|---|---|
| `sessionTitle(s)` | 显式标题优先 → 首轮内容（chat 取 `text`，否则题面）→ 截 14 字；空会话「新会话」 |
| `createSession(silent)` | `unshift` 新会话并设为当前；清 `selected / editing / showPicker`；`syncSession + persistChat`；非 silent 时 toast |
| `switchSession(id)` | 不存在或已当前则忽略；否则改 `currentId`，清 `editing / addingModel / showPicker`，`syncSession + persistChat` |
| `deleteSession(id)` | `confirm` 文案一致；过滤该会话；空则补新会话；当前被删则切首个；`syncSession + persistChat`；toast「已删除会话」 |

## 三、关键技术选型与架构决策

1. **会话操作全部放 store action**：需要同时改 `chat.sessions / currentId / rounds` 并落盘，天然属于 store；组件仅做展示与转发。
2. **`recentRounds` 用 getter 而非组件内计算**：与 `progressStats / askedCases` 同一风格；组件保持薄，便于单测直接断言数据口径。
3. **不新增展开机制**：直接复用 P2 的 `toggleRound / isRoundExpanded / collapseRound`，避免两套展开态。
4. **样式迁入 `main.css`**：与既有 `.nav-item / .sidebar-foot` 同一作用域，不引 Tailwind 原子类（这些类在原型中是成套命名样式，迁移更保真）。
5. **`nextTick` 后 `scrollIntoView`**：与 `ChatRound.expand` 同一手法，保证 DOM 更新后再定位。

## 六、交互路径说明（交付说明）

1. 进入 `/chat`（或 `/records`）→ 侧栏「评审」分组下出现「会话」与「最近评审」。
2. 「＋ 新建」置顶并切换到一个空会话；点会话项切换；hover 行尾 ✕ 删除该会话（弹确认）。
3. 「最近评审」列出当前会话已提问的题目与 `done/total`；点击展开该轮并滚动定位。
4. 切到「分析」分组 → 两块隐藏；切回「评审」→ 恢复。
5. 刷新页面 → 会话列表与当前会话由 `localStorage` 恢复。
