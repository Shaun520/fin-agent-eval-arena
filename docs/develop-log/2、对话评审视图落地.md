### 2.2 逐条对齐的交互行为（实现事实）

- **空状态**：仅当 `chat.rounds.length === 0` 渲染 `HelloPanel`；副标题里的模型数取 `activeModels.length`。
- **选题**：点 `qcard` → `pickQuestion` 写入 `chat.selected`、`showPicker=false`、`reviewMode=true`；`Composer` 用 `watch(chat.selected)` 把题干写入输入框并聚焦（等价原型的 `renderBottomBar` 里 `box.value = question`）。
- **发送**：`!reviewMode` → `askDaily`；否则优先用已选中的题，其次 `matchCase` 匹配内置题，都不中 → `createFreeQuestion` 新建自由提问。发送后清空输入框（原型通过重建 composer 达到同样效果），并 `scrollIntoView` 到该回合。
- **提问**：同一 `caseId` **复用**已有回合（刷新 `modelIds` 与 `askedAt`），否则 push 新回合；展开该回合并清 `selected/showPicker`；toast「N 个模型正在作答」。
- **流式**：`AnswerCard` 在 `onMounted` 判断 `chat.animated[key]`——未播放过则标记并 `streamText`（`delay = 本轮 modelIds 下标 × STREAM_STAGGER_MS(140ms)` 错峰起笔）；播放过则整段直出、引用直接显示。播放中渲染 `.cursor`（`v-if="streaming"`）。
- **引用浮现**：正文 `onDone` 后给 `.cite-wrap` 加 `cite-shown`（触发 `citeIn .32s`），每条 `.cite` 内联 `animationDelay = i*70ms`；无引用显示斜体「未提供任何引用来源」。
- **重播**：`play(0)` 重新流式并重新浮现引用，只作用于当前卡片。
- **收起/展开**：`chat.expandedRounds` 保存展开的回合下标（可多轮同时展开）；收起态渲染 `.round-head` + 每个模型的 `mini-score`（`reviewTotal` 为 null 显示 `—`）。
- **模型下拉**：`.model-pop2` 向上弹出；`默认模型` 行 → 切日常对话；模型行 `reviewMode=false` 时禁用；`＋新增模型` 展开内联表单（名称 + 提供方），确认后取调色板颜色、进 `active`、`reviewMode=true`。
- **删除回答**：UI 侧 `window.confirm`，store `deleteAnswer` 只做数据变更（内置 → 记入 `deleted`，自定义 → 直接移除），并把该模型移出本轮、删除其评审记录、落盘。

## 三、关键技术选型、实现思路与架构决策

1. **Composer 归属 App 而非 ChatReview（放弃 Teleport）**：原型里 composer 本就是应用级的（`renderBottomBar` 写死注入 `#bottomBar`），且 App 模板的 `.bottom-bar` 位于 `router-view` 之后，首屏进 `/chat` 时 Teleport 目标未创建。故在 `App.vue` 用 `v-if` 条件渲染，等价且稳定。
2. **流式引擎改为「可单路取消」**：原型用 DOM 直写 + 全局 `cancelStreams()`；Vue 里卡片会挂载/卸载，必须能只停自己。`streamText` 返回 `{ id, cancel }`，`onBeforeUnmount`/重播时调 `cancel()`。返回结构统一（含 `NOOP_HANDLE`），调用方无需分支。
3. **逐字文本用本地 `ref` + `onMounted` 播放**：正文是纯展示，不进 store，避免每次 tick 触发全局重渲染；跨路由/重渲染的「是否已播放」判断沿用原型的 `chat.animated[key]`（持久化字段之一）。
4. **`v-if` 与 `v-for` 不同元素混用**：Vue 3 中 `v-if` 优先级高于 `v-for`，引用列表不能用 `v-else` 挂在 `v-for` 元素上；改为 `<template v-if>` / `<template v-else>` 包裹（见 `AnswerCard`）。
5. **问题卡片与题号 chip 属「按用户要求新增」**：原型 `renderRound` 未渲染 `details.ref`、`questionGrid` 未用 `.qnum`，但原型 CSS 已预留这两组类。本阶段按用户 P2 描述补齐，复用原型类名以保证视觉不漂移。
6. **`parseCitations` 放 `lib/format.js`**：纯字符串 → 结构，属格式化工具；与 `normText`（`matchCase` 用）同层。
7. **弹层「点击外部收起」用 document 监听 + 组件内 `@click.stop`**：与其重写原型的判定条件，不如让弹层内部事件根本不冒泡到 document，彻底规避 4.2 的时序问题；`picker-pop` 与 `model-dd` 各加一处 `@click.stop`，并把原型里由「外部判定」顺带完成的「打开模型下拉时收起参考问题浮层」显式补进 `toggleModelPop`。

### 4.1 模型勾选与回合卡片的最终口径（**已生效**）

- 勾选/取消模型 → **只**改 `chat.active`，是「下一次提问用哪些模型」的开关；保留「至少保留一个模型参与回答」拦截。

- 由此，验收标准第 2 条「增/删模型后卡片实时增减」**作废**（用户明确要求），`syncRoundModels` 已删除，代码回归原型语义。

## 六、交互路径说明（交付说明）

1. 进 `/chat`：⚖ 问候 + 6 张参考问题卡（FQ-001…FQ-006，各自显示「已评测 0 / 4 条回答」）；底栏 composer 常驻（不随内容滚动）。
2. 点卡片 → 卡片蓝框高亮、题干带入输入框并聚焦 → 「发送」（或 Ctrl/Cmd+Enter）。
3. 依次出现：蓝色右对齐气泡 → meta（N 个模型作答 · 时间 · 本轮进度 0/N · 收起）→ 问题卡片（题号/标题/题干/信息截止/risk chips + 可展开的「参考答案与允许证据」）→ 2 列答案网格。
4. 4 张卡错峰逐字输出 + 闪烁光标；正文结束后「引用与证据（N）」整块淡入、各条引用自上而下递延浮现；引用为蓝色 `.cite-link`（悬停下划线+浅蓝底、focus 蓝框、点击不跳转）。
5. 「模型选择」：取消/勾选只影响下一次提问；「＋新增模型」填名称+提供方后进 `active`。

7. ✕ 删除回答 → 确认后卡片消失、该模型移出本轮；刷新后删除状态保持（内置走 `faeval.v1.answers.deleted`，自定义直接移除）。
8. ↻ 重播该卡的流式与引用浮现；收起/展开按钮切换回合折叠（收起显示各模型 `mini-score`）。
